# الأنظمة والخوارزميات

> كل نظام هنا منفّذ أو موصوف بدقة كافية للتنفيذ. ما هو منفّذ في `src/` مُعلَّم بـ✅، والباقي مخطط تنفيذي.

---

## 1. موجّه القدرات ✅ `src/core/router.ts`

**المشكلة:** 60 مزوّدًا، لكل منهم حصة مختلفة، جودة مختلفة، أعطال مختلفة. لا يجوز أن يعرف كود الإنتاج أسماءهم.

```ts
score = 0.35·quality + 0.25·reliability + 0.20·headroom − 0.15·risk − 0.05·latency
```

| المكوّن | القياس | التحديث |
| --- | --- | --- |
| quality | من ثقة الكتالوج + نوع القدرة | يدوي + تقييم QC |
| reliability | EWMA للنجاح، α=0.2 | كل مهمة |
| headroom | `remaining / allowance` | من الدفتر |
| risk | low=0, medium=.5, high=1 | من الكتالوج |
| latency | EWMA بالمللي ثانية | كل مهمة |

**القاطع:** 3 حالات فشل متتالية → إيقاف `30s × 2^(n−1)` بحد أقصى 30 دقيقة. نجاح واحد يصفّره.
**الاستبعاد:** قدرة غير موجودة، رصيد صفر، قاطع مفتوح، موقع محظور سياسيًا.

## 2. دفتر الرصيد والميزانية اليومية ✅ `src/core/ledger.ts`

المفتاح = `siteId:periodKey` حيث `periodKey` يُحسب بإزاحة المنطقة الزمنية للمزوّد:

```
day   : YYYY-MM-DD (بعد الإزاحة)
week  : YYYY-Www
month : YYYY-MM
once  : "once"
```

### موزّع الميزانية (Knapsack محدود)

```
لكل فيديو: احتياج = {صور: 8، مقاطع: 8، صوت: 450 حرف، موسيقى: 1}
الهدف: تعظيم عدد الفيديوهات مع قيد Σ(pieces × cost_i) ≤ quota_i × 0.8
الحل: تخصيص جشع مرتّب حسب (جودة/تكلفة)، ثم تحسين محلي بتبديل مزوّد واحد
```

الـ20% المحجوزة ليست ترفًا: معدل فشل توليد الفيديو 30–40% في الذروة، وكل إعادة محاولة تكلّف رصيدًا.

## 3. خط الأنابيب ذو الحواجز ✅ `src/core/pipeline.ts`

- كل مرحلة: `run(ctx) → Artifact[]`، مع `maxAttempts`, `timeoutMs`, `gates`.
- `checkpoint` يمنع إعادة إنفاق الرصيد عند الاستئناف.
- backoff: `500ms × 2^(attempt−1) + jitter(0..250)`.
- كل حدث يُبَث (`stage:start/done/failed`, `gate:failed`) للتليمِتري.

**قاعدة ذهبية:** المرحلة تُعيد كتابة مخرجاتها فقط، ولا تعتمد على ترتيب سابق غير مُسجَّل في checkpoint.

## 4. اختيار النمط — Thompson Sampling

نريد معرفة أي تركيبة (نوع Hook × سرعة المونتاج × نوع الصوت) تحقق احتفاظًا أعلى، مع استمرار الاستكشاف.

```
لكل نمط a: نجاحات α_a، إخفاقات β_a (Beta prior 1,1)
اختر a ~ argmax Beta(α_a, β_a)
مكافأة r = 0.5·watch_ratio + 0.3·retention_3s + 0.2·CTR
حدّث: α += r، β += (1−r)
```

تُحدَّث كل 24 ساعة بعد جمع إحصاءات يوتيوب. الحد الأدنى للعينة: 30 ظهورًا قبل اعتماد نمط.

## 5. بوابة الجودة (Ensemble)

| المقياس | الحساب | الحد | عند الفشل |
| --- | --- | --- | --- |
| حِدّة | تباين لابلاسيان | > 80 | إعادة اللقطة |
| وجه | MediaPipe landmarks | > 0.85 | إعادة ببرومبت أوضح |
| اتساق | CLIP cosine بين اللقطات | > 0.78 | img2img من المرجع |
| نص | OCR confidence | > 0.80 | إعادة بخط أوضح |
| جهارة | loudnorm | −16…−12 LUFS | تطبيع |
| تكرار | pHash Hamming | > 8 | حذف/استبدال |

**قرار مركّب:** `accept if 5/6 pass and no critical fail`. «الحرج» = وجه مشوّه أو فيديو تالف.

## 6. إصلاح المحدّدات (Selector Healing)

كل مهايئ يخزّن «خريطة عناصر» مع 3 بدائل مرتّبة:

```
1. data-testid / name / aria-label (مستقر)
2. role + accessible name (متوسط)
3. CSS path + نص مرئي (هش)
4. مرساة بصرية (لقطة شاشة + مطابقة) (آخر حل)
```

عند فشل العنصر: نجرّب البدائل بالترتيب، ونسجّل أي بديل نجح. إذا نجح بديل غير الأول مرتين → يُرقّى تلقائيًا. إذا فشل الكل → إشعار «الواجهة تغيّرت» مع لقطة شاشة وHTML مقتطع.

```ts
async function resolve(locator: LocatorMap, page: Page) {
  for (const candidate of locator.candidates) {
    const el = page.locator(candidate.selector).first();
    if (await el.count()) return { el, candidate };
  }
  throw new UiDriftError(locator.name);
}
```

## 7. التقاط الشبكة: HAR → API داخلي

الهدف: استبدال 30 خطوة DOM بطلب HTTP واحد.

```
1. افتح الصفحة مع CDP: Network.enable
2. سجّل الطلبات أثناء توليد يدوي واحد
3. فلترة: application/json + method POST + host المزوّد
4. أعد تشغيل الطلب خارج المتصفح مع نفس الـheaders/cookies
5. تحقّق من الاستجابة، ثم ثبّت العقد في adapter
6. راقب: إن تغيّر شكل الاستجابة → عودة تلقائية إلى DOM
```

**قاعدة:** لا تستخدم هذا المسار إلا إذا كان الطلب لا يحمل توقيعًا مولّدًا من JS. إن وُجد توقيع (مثل بعض حجب Cloudflare)، ابقَ على المتصفح.

## 8. مترجم البرومبت (Prompt DSL)

الفكرة: وصف بصري واحد → لهجة كل مزوّد.

```json
{
  "subject": "شاب يجلس أمام حاسوب في غرفة مظلمة",
  "shot": { "size": "medium", "angle": "eye-level", "lens": "35mm" },
  "light": { "key": "screen-glow", "rim": "cool-blue" },
  "motion": { "camera": "slow-push-in", "subject": "typing" },
  "style": { "look": "cinematic", "grain": "fine", "palette": "teal-orange" },
  "negative": ["text", "watermark", "extra fingers"]
}
```

| المزوّد | اللهجة |
| --- | --- |
| Kling | جملة واحدة وصفية + `camera movement:` صريح |
| Veo | أسلوب سردي كامل + تفاصيل الإضاءة |
| Wan | وصف مباشر قصير + `negative prompt` منفصل |
| Flux/SD | تاجات مفصولة بفواصل + أوزان `(x:1.2)` |
| Suno | `genre, mood, tempo, instruments, vocals` |

المترجم دالة نقية `compile(dsl, provider) → string`، وكل تغيير يُختبر على 20 برومبت ذهبي.

## 9. منع التكرار


## 10. نشر بلا تكرار (Exactly-once)

```
idempotency_key = sha256(account + file_hash + title)
جدول publications(key, status, video_id, attempts)
INSERT ... ON CONFLICT DO NOTHING → إن وُجد سجل ناجح، أعد نتيجته
إن وُجد سجل "in_flight" أحدث من 10 دقائق → اعتبره مجهولًا وراجع يدويًا
```

**حالة «مجهول»:** الرفع قد يكون نجح دون استجابة. لا تُعد المحاولة تلقائيًا؛ افحص قائمة الفيديوهات أولًا (قاعدة التشغيل الواحد).

---

## 11. المراقبة الذاتية (Watchdog)

حالة كل مزوّد: `healthy → degraded → open → half-open`.

| الانتقال | الشرط |
| --- | --- |
| healthy→degraded | فشلان خلال 10 دقائق |
| degraded→open | 3 حالات فشل متتالية |
| open→half-open | بعد انتهاء الـcooldown |
| half-open→healthy | نجاح واحد |
| half-open→open | فشل واحد |

كل 5 دقائق: فحص خفيف (فتح الصفحة، وجود زر التوليد، رصيد ظاهر). النتيجة تُحدّث `SuccessEwma` بلا استهلاك رصيد.

## 12. حاكم التكلفة وKill Switch

```
daily_budget_credits = Σ quota_i × 0.8
spent_today = Σ actual_spend
if spent_today > 0.85 × budget → جدولة المهام غير الحرجة للغد
if spent_today ≥ budget → إيقاف كل التوليد، إبقاء النشر والتحليل
kill_switch → إلغاء المهام غير المنشورة، إغلاق المتصفحات، لا رفع
```

## 13. توقّع الاحتفاظ (Hook Scoring)

نموذج خفيف (GBDT) على ميزات: طول الجملة الأولى، وجود سؤال، رقم، تناقض، نص على الشاشة، سرعة أول 3 ثوان.
المخرج: احتمالية تجاوز 3 ثوان. يُستخدم لترتيب 5 صيغ Hook واختيار الأفضل قبل التوليد — يوفر رصيدًا كان سيُصرف على نسخ سيئة.
