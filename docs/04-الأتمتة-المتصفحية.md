# الأتمتة المتصفحية — التعامل مع واجهة بلا API

> هذا المستند هو دليل بناء مهايئ (adapter) لأي موقع مجاني. الفكرة: **عقد واحد، ثلاث تقنيات تحكم، ومراقبة تجعل الانهيار مرئيًا قبل أن يكلّف رصيدًا.**

---

## 1. طبقة الواقع

```
Orchestrator
   │  withSession(spec)  ← قفل لكل موقع، منع التزامن
   ▼
BrowserRealityLayer (src/automation/session.ts)
   │  open(profile) → probe() → run()
   ▼
Playwright / CDP
   │  ملف تعريف دائم: cookies + localStorage + IndexedDB
   ▼
الموقع (Kling / Dreamina / YouTube Studio / …)
```

**لماذا ملف تعريف دائم؟** تسجيل الدخول هو أغلى خطوة بشرية. ملف تعريف واحد لكل حساب/موقع يعني أن إعادة تشغيل الخدمة لا تُفقد الجلسة، ويمكن نسخه احتياطيًا مشفّرًا.

```ts
const spec: BrowserSessionSpec = {
  siteId: 'kling',
  profileDir: '.profiles/kling/main',
  headless: true,
  locale: 'en-US',
  timezoneId: 'UTC',
  proxyUrl: process.env.KLING_PROXY,
};
```

## 2. شجرة قرار: أي تقنية تحكم؟

```
هل يوجد API رسمي مجاني؟
├── نعم → استخدمه (ElevenLabs, Pollinations, HF, D-ID)
└── لا
    ├── هل طلبات الواجهة نظيفة (JSON بلا توقيع JS)؟
    │   ├── نعم → HAR→API (أسرع 10–50×)
    │   └── لا  → أتمتة DOM
    └── هل الواجهة معقدة جدًا/متغيرة؟
        └── وكيل رؤية (browser-use / Skyvern) كخيار أخير
```

| التقنية | السرعة | الهشاشة | الاستهلاك |
| --- | --- | --- | --- |
| API رسمي | عالية | منخفضة | رصيد/مفتاح |
| HAR→API | عالية | متوسطة | رصيد الموقع |
| DOM | منخفضة | عالية | رصيد الموقع |
| وكيل رؤية | منخفضة جدًا | متوسطة | توكنز + رصيد |

## 3. من DOM إلى API داخلي — 8 خطوات

1. شغّل Chromium مع `--remote-debugging-port=9222`.
2. `Network.enable` عبر CDP، وسجّل أثناء **توليد يدوي واحد** ناجح.
3. احفظ `.har` وفِلتر: `POST` + `application/json` + نطاق المزوّد.
4. أعد الطلب من `fetch` خارج المتصفح بنفس الكوكيز والهيدرات.
5. إن نجح: ثبّت العقد في `adapter.http.ts` مع `TokenBucket`.
6. إن فشل بسبب توقيع/Cloudflare: عُد إلى DOM ولا تحاول تجاوز الحماية.
7. أضف اختبارًا يوميًا: طلب واحد رخيص يتحقق من شكل الاستجابة.
8. خزّن نسخة من الاستجابة المرجعية (fixture) لكشف التغيير.

```ts
// عقد داخلي نموذجي
interface KlingInternal {
  createTask(input: { prompt: string; image?: string; duration: 5 | 10 }): Promise<{ taskId: string }>;
  poll(taskId: string): Promise<{ status: 'running' | 'done' | 'failed'; url?: string }>;
  download(url: string, dest: string): Promise<string>;
}
```

## 4. أتمتة DOM — قواعد البقاء

| القاعدة | التطبيق |
| --- | --- |
| لا تعتمد على `nth-child` | استخدم `getByRole` + الاسم |
| انتظر الحالة لا الزمن | `waitForResponse`, `expect(locator).toBeEnabled()` |
| تحقق من النجاح | وجود عنصر النتيجة/زر التنزيل، لا مجرد اختفاء السبينر |
| التقط الأدلة | لقطة شاشة + HTML عند كل فشل |
| لا تكرّر النقر | بعد النقر، انتظر تغيّر الحالة؛ النقر المزدوج يستهلك رصيدين |
| نظّف التنزيلات | مجلد مؤقت لكل مهمة، وحذف بعد النقل |
| استخدم `acceptDownloads` | مسار التنزيل عبر حدث `download` لا البحث في القرص |

### مثال: توليد في Kling

```ts
await page.goto('https://app.klingai.com/global/');
await page.getByRole('button', { name: /create|video/i }).click();
const editor = page.getByRole('textbox').first();
await editor.fill(compiledPrompt);
await page.getByRole('button', { name: /generate/i }).click();

// النجاح = ظهور فيديو أو زر تنزيل، لا اختفاء السبينر
const result = page.locator('[data-testid="generation-result"], video').first();
await result.waitFor({ state: 'visible', timeout: 10 * 60_000 });

const download = page.waitForEvent('download');
await page.getByRole('button', { name: /download/i }).click();
const file = await download;
await file.saveAs(dest);
```

> لاحظ: المحدّد `data-testid` قد لا يوجد؛ الخريطة تحمل 3 بدائل، والإصلاح التلقائي يرقّي الناجح.

## 5. التحديات البشرية

| التحدي | السلوك الصحيح |
| --- | --- |
| كابتشا | إيقاف المهمة، إشعار، فتح المتصفح للمستخدم، ثم استئناف |
| 2FA | طلب الرمز من المستخدم، لا تخزينه |
| «تحقق أنك لست روبوتًا» | تسليم كامل للبشر |
| موافقة شروط جديدة | عرض النص، طلب موافقة صريحة |
| حظر مؤقت | احترام المدة، تبديل الحساب لا التجاوز |

**لا يوجد في هذا المشروع أي كود لكسر كابتشا أو تجاوز Cloudflare.** `QueueBroker` في النواة يعيد `timeout` افتراضيًا حتى يقرر الإنسان.

| --- | --- | --- | --- |
| Kling | 3 دقائق | 1 | 80% من الحصة |

## 7. وصفة بناء مهايئ جديد (7 خطوات)

1. **سجّل يدويًا** وأنت تراقب الشبكة (DevTools → Network → Save all as HAR).
2. **حدّد مسار النجاح**: ما الذي يظهر عند النجاح؟ وما الذي يظهر عند نفاد الرصيد؟
3. **اكتب `healthCheck`**: هل الجلسة صالحة؟ هل الرصيد > 0؟ هل الزر موجود؟
4. **اكتب `run`**: ثلاث محاولات كحد أقصى، وكل محاولة تتحقق من النتيجة.
5. **اكتب `collect`**: تنزيل الأصول إلى مخزن الأصول مع التحقق من النوع والحجم.
6. **أضف fixtures**: استجابة ناجحة، استجابة «رصيد صفر»، استجابة تغيّر الواجهة.
7. **سجّل في الكتالوج**: `access`, `confidence`, `limits`, `verifiedAt`.

```ts
export class DreaminaAdapter implements SiteAdapter<ShotRequest, ClipResult> {
  siteId = 'dreamina';
  capability = 'text2video' as const;

  async healthCheck() {
    return this.page.getByRole('button', { name: /generate/i }).isVisible();
  }

  async run(input: ShotRequest): Promise<ClipResult> {
    await this.fillPrompt(input.prompt);
    await this.selectRatio('9:16');
    await this.selectDuration(input.duration);
    const before = await this.countResults();
    await this.submitOnce();
    const url = await this.waitForNewResult(before);
    return { url, provider: this.siteId, prompt: input.prompt };
  }

  async collect(result: ClipResult, dest: string) {
    return [await download(result.url, dest)];
  }
}
```

## 8. تصنيف الأعطال

| العطل | العلامة | العلاج |
| --- | --- | --- |
| `UiDrift` | عنصر غير موجود بعد 3 بدائل | لقطة + HTML، إيقاف الموقع، تنبيه |
| `QuotaExhausted` | رسالة ترقية/رصيد صفر | خصم الرصيد، تبديل مزوّد |
| `AuthExpired` | إعادة توجيه لتسجيل الدخول | طابور بشري |
| `RateLimited` | 429/403 | cooldown متزايد |
| `GenerationFailed` | فشل بعد القبول | إعادة مرة واحدة ثم تبديل |
| `DownloadBroken` | ملف 0 بايت/HTML | إعادة التنزيل، ثم فشل |
| `PolicyBlocked` | موقع高风险 غير مسموح | رفض قبل البدء |

## 9. المراقبة

- معدل نجاح لكل مهايئ (EWMA) — يراه الموجّه.
- زمن كل خطوة (فتح، إدخال، توليد، تنزيل).
- عدّاد `UiDrift` لكل موقع — إن تجاوز 1/ساعة، أوقف الموقع.
- لقطات شاشة للفشل فقط (وليس لكل خطوة) لتوفير المساحة.
- **اختبار دخان يومي** لكل مهايئ نشط: فتح + وجود زر + قراءة الرصيد، بلا توليد.

## 10. الامتثال — بصراحة

1. أتمتة واجهة قد تخالف شروط الخدمة حتى لو كانت «مجانية». كثير من المواقع تمنع «الاستخدام الآلي» صراحة.
2. الحساب قد يُحظر، والمخرجات قد تفقد حقوقها التجارية تلقائيًا.
3. الأرصدة المجانية ليست موردًا مضمونًا؛ تتغير الأسعار والحدود شهريًا.
4. لذلك: المسار المجاني للاستكشاف، والمسار الرسمي/المحلي للإنتاج. الكتالوج يحمل `risk` و`confidence`، والحارس يمنع المخاطر العالية افتراضيًا.
5. لا تُخزّن كلمات مرور نصية. استخدم ملف تعريف المتصفح + كوكيز، وشفّر النسخ الاحتياطية.
6. لا تشارك حسابات بين أجهزة/دول متعددة؛ هذا أقرب سبب للحظر.
